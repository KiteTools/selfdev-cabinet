# Вымышленные примеры для проверки установки

Все тексты, идентификаторы и даты созданы для тестирования. Они не представляют реальных людей, консультации, контакты или частные наборы данных. Исходные примеры написаны по-английски и используются в обеих языковых версиях документации.

| Файл | Назначение |
| --- | --- |
| [diary.json](diary.json) | `POST /api/diary`; создаёт вымышленный дневник успеха |
| [razbor-session.json](razbor-session.json) | `POST /api/razbor-session-ingest`; сохраняет вымышленный итог сессии |
| [crm-activity.json](crm-activity.json) | `POST /api/crm-activity-ingest`; записывает вымышленное событие задачи и ставит его текст в очередь сигналов |
| [link-signal.json](link-signal.json) | `POST /api/link-signals-ingest`; ставит отдельный вымышленный сигнал в очередь |
| [transcript.txt](transcript.txt) | Короткий UTF-8-транскрипт для загрузки и саммари |

До отправки JSON в свою тестовую установку замените `sp_contact_id` на контакт своего тестового аккаунта, уже прошедшего вход в приложение. Используйте нужный заголовок из инструкции SendPulse. Здесь нет реквизитов доступа; это не готовые запросы к production. Для отчётов периода замените вымышленные даты событий датами своего теста; дата дневника определяется при получении. Открытие этой папки не выполняет запросы.
