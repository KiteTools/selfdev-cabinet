# Установка Личного кабинета: инструкция оператора

Разверните собственное приложение со своим Telegram-ботом, сайтом Netlify, базой Neon PostgreSQL и аккаунтом SendPulse. Инструкция составлена по публичным исходникам: она описывает воспроизводимую настройку и проверку результата. Она **не подтверждает** работоспособность живого развёртывания, сценария бота, доставки email или результата ИИ.

Приложение даёт вход через Telegram, редактирование личного контекста, историю дневников и разборов, саммари консультаций, документы понимания, связки фокуса и обзоры периода. Сценарии SendPulse, расписания, распознавание голоса и инструкции ИИ-бота настраиваются отдельно — по [комплекту настройки SendPulse](sendpulse-setup.ru.md). Экспорт частного аккаунта и база подписчиков не входят в поставку.

## Осознанно выберите способ доставки

| Режим | Настройка | Что происходит |
| --- | --- | --- |
| Полная установка с SendPulse | `CABINET_TRANSPORT=sendpulse` | Личность Telegram связывается с контактом настроенного SendPulse-бота; изменения сопоставленных полей отправляются этому контакту |
| Приложение без доставки в бот | `CABINET_TRANSPORT=local` (по умолчанию) | Telegram-вход и база приложения по-прежнему нужны; состояние сохраняется в вашем развёртывании без доставки в SendPulse |

Основной маршрут этой инструкции — **SendPulse**. Если оставить `local`, успешное сохранение не означает, что данные дошли до бота. Локальный адаптер не делает приложение офлайн: остаются внешние авторизация и база, а при включении соответствующих функций — OpenAI и email.

## 1. Подготовьте аккаунты и инструменты

- Node.js 22.9.0 или новее и npm для установки зависимостей, проверок и сборки сайта.
- Аккаунт Netlify с нужными Functions и Background Functions; проверьте ограничения своего тарифа.
- Пустая база Neon PostgreSQL под вашим управлением. Для production и тестовых развёртываний используйте разные базы.
- Клиентские инструменты PostgreSQL: `psql`, `pg_dump`, `pg_restore` для схемы и резервных копий.
- Токен и имя Telegram-бота от BotFather. Для режима SendPulse подключите именно этого бота к своему аккаунту SendPulse с доступным API Request.
- Проект и API-ключ OpenAI, только если нужны ИИ-функции. Подписка ChatGPT не является API-ключом.
- SMTP-реквизиты и разрешённый адрес отправителя, только если нужна отправка отчётов по email.

Клонируйте репозиторий и просмотрите ревизию, которую собираетесь развернуть. Выполняйте команды из корня репозитория приложения:

```sh
npm ci
npm test
npm run build
```

Netlify использует скрипт сборки из репозитория и публикует созданный каталог `dist`. Не публикуйте корень репозитория: миграции, операторские скрипты, файлы окружения и серверные исходники не являются ресурсами сайта. Каталог Functions `netlify/functions` остаётся отдельно от `dist`.

## 2. Настройте окружение

Выполните `npm run setup`: команда создаст локальный игнорируемый `.env` по [`.env.example`](../.env.example). Скрипт генерирует независимые случайные секреты приложения и не перезаписывает существующий файл. Заполните остальные настройки данными своих аккаунтов. Для развёртывания внесите эквивалентные значения в настройки окружения Netlify с доступом Functions и в нужный контекст публикации. Локальный `.env` не становится автоматически хранилищем секретов сервера. Не коммитьте его и не загружайте как статический файл.

Если задаёте секреты вручную, создайте независимые случайные значения `JWT_SECRET`, `LK_SERVICE_SECRET` и `SENDPULSE_DIARY_SECRET` через менеджер паролей или безопасный генератор. `JWT_SECRET` должен содержать не менее 32 символов; используйте случайные секреты, а не осмысленные фразы. Передавайте в серверный блок SendPulse API Request только секрет соответствующего маршрута.

### Основные настройки приложения и доставки

| Переменная | Тип и назначение | Когда нужна |
| --- | --- | --- |
| `CABINET_TRANSPORT` | `local` или `sendpulse` | Явно укажите выбранный режим |
| `DATABASE_URL` или `NETLIFY_DATABASE_URL` | Строка подключения к Neon PostgreSQL; приоритет у `DATABASE_URL` | Всегда |
| `TELEGRAM_BOT_TOKEN` | Секретный токен бота | Всегда, включая local |
| `TELEGRAM_BOT_USERNAME` | Имя бота без `@` | Всегда |
| `JWT_SECRET` | Случайный секрет подписи сессий, не менее 32 символов | Всегда |
| `TELEGRAM_AUTH_MAX_AGE_SECONDS` | Положительное целое; срок свежести подписанного Telegram-входа, по умолчанию 900 секунд | Необязательно |
| `BOT_TIMEZONE` | Часовой пояс IANA для расписания бота и дат по умолчанию; по умолчанию `UTC` | Задайте явно и согласуйте с расписаниями SendPulse |
| `SENDPULSE_CLIENT_ID` | Идентификатор OAuth-клиента SendPulse | Режим SendPulse |
| `SENDPULSE_CLIENT_SECRET` | Секрет OAuth-клиента SendPulse | Режим SendPulse |
| `SENDPULSE_BOT_ID` | ID подключённого Telegram-бота внутри SendPulse | Режим SendPulse |
| `SENDPULSE_DIARY_SECRET` | Общий секрет `/api/diary` | При приёме дневников |
| `LK_SERVICE_SECRET` | Сервисный секрет приёма событий и привилегированного входа CLI | При использовании этих маршрутов |
| `LK_SERVICE_RATE_LIMIT` | Положительное целое, запасной предел сервисных запросов; по умолчанию 120 | Необязательно |
| `LK_SERVICE_RATE_WINDOW_MINUTES` | Положительное целое, окно ограничения; по умолчанию 10 минут | Необязательно |

Часть маршрутов задаёт свои пределы: вход CLI — 60, приём сессий разбора — 120, CRM и сигналы связок — 240 за настроенное окно. Эти значения имеют приоритет над общим запасным пределом. Ограничения используют таблицу аудита; при отсутствии или недоступности этой таблицы нельзя считать их надёжной защитой. Примените все миграции и отслеживайте ошибки.

`LK_SERVICE_SECRET` разрешает привилегированные серверные действия, включая `/api/auth-cli`: этот маршрут выдаёт сессию **существующего** пользователя по `user_id` или `sp_contact_id`. Это не публичный вход и не API регистрации. Не передавайте секрет браузеру и не выпускайте CLI-сессии пользователей без полномочий.

### Необязательные настройки операторского CLI

CLI — административный клиент вашего развёртывания, а не второй сервер и не публичный способ входа. До вызова команды прочитайте её справку: некоторые команды записывают данные или запускают платную ИИ-обработку. Smoke-проверка реального аккаунта не является офлайн-тестом.

| Переменная | Назначение |
| --- | --- |
| `LK_BASE_URL` | Адрес вашего приложения; по умолчанию `http://localhost:8888` |
| `LK_CLI_SP_CONTACT_ID` | Существующий тестовый контакт, с которым вы уполномочены работать; альтернатива UUID пользователя |
| `LK_CLI_USER_ID` | UUID существующего пользователя приложения, с которым вы уполномочены работать |
| `LK_CLI_OUTPUT` | Формат вывода CLI; по умолчанию `text` |
| `LK_CLI_TIMEOUT_MS` | Таймаут запроса в миллисекундах; по умолчанию 30 000 |

CLI использует `LK_SERVICE_SECRET`. В отличие от npm-команд проверки настроек и миграций, `npm run cli` не загружает `.env` автоматически. Подготовьте окружение явно или прочитайте справку с этим файлом через `node --env-file=.env cli/index.mjs --help`. Храните идентификаторы и выданные сессии в частном доступе.

### Настройки ИИ

| Переменная или группа | Назначение |
| --- | --- |
| `OPENAI_API_KEY` | Серверный API-ключ OpenAI |
| `OPENAI_MODEL` | Явно выбранная модель, доступная вашему API-проекту; запасное значение в исходнике не гарантирует доступ к ней |
| `OPENAI_MAX_OUTPUT_TOKENS` | Необязательный положительный предел токенов ответа; без него этот предел явно не передаётся |
| `OPENAI_TIMEOUT_MS` | Таймаут запроса в миллисекундах; значение по умолчанию и верхний предел — 600 000 |
| `OPENAI_REASONING_EFFORT` | `minimal`, `low`, `medium`, `high` или `xhigh`; по умолчанию `high`; передаётся только для поддерживаемого исходником выбора модели |
| `OPENAI_DIARY_MODEL`, `OPENAI_DIARY_MAX_OUTPUT_TOKENS`, `OPENAI_DIARY_TIMEOUT_MS` | Переопределения саммари дневников; при отсутствии используются базовые настройки |
| `OPENAI_POSTER_MODEL`, `OPENAI_POSTER_MAX_OUTPUT_TOKENS`, `OPENAI_POSTER_TIMEOUT_MS` | Переопределения генерации промптов плаката |
| `OPENAI_RAZBOR_MODEL`, `OPENAI_RAZBOR_MAX_OUTPUT_TOKENS`, `OPENAI_RAZBOR_TIMEOUT_MS` | Переопределения генерации документа понимания |
| `OPENAI_LINKS_MODEL`, `OPENAI_LINKS_MAX_OUTPUT_TOKENS`, `OPENAI_LINKS_TIMEOUT_MS` | Переопределения анализа сигналов связок |
| `OPENAI_RETRO_MODEL`, `OPENAI_RETRO_MAX_OUTPUT_TOKENS`, `OPENAI_RETRO_TIMEOUT_MS` | Переопределения обзора периода |
| `TRUNCATE_HEAD_CHARS` | Число начальных символов входа консультации, по умолчанию и максимум — 12 000 |
| `TRUNCATE_TAIL_CHARS` | Число конечных символов входа консультации, по умолчанию и максимум — 8 000 |
| `DIARY_INPUT_MAX_CHARS` | Бюджет входного текста саммари дневников, по умолчанию 30 000 символов |
| `POSTER_INPUT_MAX_CHARS` | Бюджет исходника промптов плаката, по умолчанию 3 500 символов |

Выберите модель, совместимую с Responses API, нужными форматами структурированного вывода и настройкой reasoning. До увеличения нагрузки проверьте небольшой вымышленный пример. Переменные окружения приложения не настраивают ИИ-блок SendPulse. Генерация плаката возвращает **текстовые промпты**, а не файлы изображений. Длинный вход консультации сокращается до начала и конца; такое саммари не доказывает охват всего транскрипта.

### Настройки почты

| Переменная | Назначение |
| --- | --- |
| `SMTP_HOST`, `SMTP_PORT` | SMTP-сервер и числовой порт; по умолчанию 587; порт 465 включает неявный TLS |
| `SMTP_USER`, `SMTP_PASS` | Учётные данные SMTP |
| `MAIL_FROM` | Разрешённый адрес отправителя |
| `MAIL_REPLY_TO` | Необязательный адрес для ответов; по умолчанию отправитель |
| `MAIL_BCC` | Необязательный дополнительный получатель; задавайте только при явном намерении отправлять туда копию каждого отчёта |

Старые имена `SENDPULSE_SMTP_HOST`, `SENDPULSE_SMTP_PORT`, `SENDPULSE_SMTP_USER`, `SENDPULSE_SMTP_PASS` поддерживаются как запасные. SMTP может обслуживать SendPulse или другой провайдер. Без настроек SMTP отправка не включается: попытка отправить письмо завершится ошибкой, а сохранённый отчёт останется в приложении. До проверки подтвердите отправителя или домен по правилам провайдера. Не задавайте скрытого стороннего получателя BCC.

Проверьте локальные настройки без вывода значений:

```sh
npm run check:env
```

## 3. Создайте схему базы

Для первой установки используйте пустую базу. Сначала просмотрите план миграций, затем явно примените его:

```sh
npm run migrate
npm run migrate -- --apply
```

Первая команда показывает все файлы миграций без подключения к базе и не устанавливает, какие уже применены. Команда применения использует `psql`, транзакцию и контрольные суммы, пропуская совпадающие ранее учтённые миграции. Примените все ожидающие номерные миграции, включая таблицы сервисного аудита: при неполной схеме часть интерфейса может работать, а отдельные сценарии — падать.

В схеме хранятся связи пользователей и контактов, личное состояние и версии, результаты консультаций, дневники и их саммари, документы понимания, связки, очереди сигналов и предложения, CRM-события, события прогресса, обзоры периода, сессии разбора, успехи и аудит сервисных запросов. В режиме SendPulse база также хранит кеш OAuth-токена. Считайте резервную копию базы конфиденциальной, даже если исходники открыты.

Не импортируйте чужую базу ради запуска установки. Первый Telegram-вход создаст вашу собственную связь пользователя с контактом и начальное состояние. Версии состояния — ограниченные снимки, а не резервные копии всей базы.

## 4. Разверните приложение и подключите Telegram

1. Импортируйте проверенный репозиторий в свой аккаунт Netlify. Используйте `netlify.toml`: команда сборки `npm run build`, каталог публикации `dist`, каталог Functions `netlify/functions`.
2. Добавьте окружение из шага 2 в нужный контекст развёртывания. Для preview используйте отдельные тестовые базу, бота и реквизиты. Preview с production-реквизитами может писать в рабочие данные.
3. Выполните deploy и проверьте журналы сборки и Functions на отсутствие настроек и ошибки упаковки. Не копируйте частные тела запросов в публичные issues.
4. Откройте свой HTTPS-адрес. Проверьте `GET /api/config`: публичное имя бота и режим доставки должны соответствовать вашей установке, секретов в ответе быть не должно. `GET /api/me` без авторизации не должен возвращать пользователя.
5. Задайте домен приложения через BotFather `/setdomain` для настроенного Telegram-бота. Эта привязка описана в [документации Telegram Login Widget](https://core.telegram.org/widgets/login/).
6. Для SendPulse завершите [цепочку регистрации](sendpulse-setup.ru.md#1-подключите-бота-и-настройте-регистрацию). Подписчик должен отправить `/start` и пройти Telegram-вход в приложение, прежде чем можно будет назначать ему входящие события.
7. В режиме local откройте приложение и войдите через Telegram без параметра контакта SendPulse. Адаптер использует ключ `local:<telegram_id>` в существующей схеме. Не настраивайте SendPulse-цепочку на угадывание или использование этих внутренних ключей.

Загрузившаяся страница ещё не подтверждает авторизацию, запись в базу, доставку в бот, выполнение фоновой задачи или отправку email. Проверьте их отдельно.

## 5. Как работают фоновые задачи

Браузер создаёт запись, вызывает фоновую функцию и затем опрашивает статус. Netlify Background Functions сначала возвращают `202` о принятии; это **не** готовый отчёт. Платформа указывает до 15 минут выполнения; проверьте поддержку тарифом и предел размера запроса. [Netlify Background Functions](https://docs.netlify.com/build/functions/background-functions/)

| Процесс | Запуск | Фоновый запрос | Чтение статуса |
| --- | --- | --- | --- |
| Консультация | `POST /api/summarize-start`, JSON `{"summary_type":"one_on_one"}` или `"topics"` | `POST /api/summarize-background?id=<id>`, multipart form | `GET /api/summarize-status?id=<id>` |
| Период дневников | `POST /api/diaries-summary-start`, JSON `{"date_from":"YYYY-MM-DD","date_to":"YYYY-MM-DD"}` | `POST /api/diaries-summary-background?id=<id>` | `GET /api/diaries-summary-status?id=<id>` |
| Обзор периода | `POST /api/retro-start`, JSON с `date_from` и `date_to` | `POST /api/retro-background?id=<id>` | `GET /api/retro-status?id=<id>` |

Используйте авторизованный интерфейс приложения: это не webhook-маршруты SendPulse. Multipart-поля консультации: `consultationId`, `summaryType`, обязательный файл `transcript`, необязательный файл `notes`, необязательный `email`. Защитное поле `company` оставьте пустым. Нужны текстовые файлы UTF-8; для `.vtt` очищается разметка субтитров. Загрузчик не декодирует `.pdf`, аудиозапись или Word. Предел приложения — 5 MiB на файл; лимит запроса у провайдера может быть ниже.

Для консультаций допускается пять запусков на пользователя за 24 часа. Период дневников ограничен 90 днями и должен содержать записи. Готовый результат остаётся в базе для чтения интерфейсом. Проверяйте `status` (`processing`, `completed`, `failed`) и `error_message`; принятие задачи не равно завершению. Фоновая задача консультации закрепляется за одним запуском: повтор не начинает второй запуск и не генерирует готовый результат заново. Внутренняя отметка обработчика `already_started` не заменяет проверку статуса задачи через платформу. При зависании проверьте статус и очищенные серверные журналы до создания новой задачи, чтобы избежать повторной оплаты работы.

Генерация саммари консультации не применяет автоматически все извлечённые поля. Для предварительного просмотра используется `POST /api/summarize-apply` с `consultation_id`, `selected_fields`, `preview:true`; после проверки примените выбранное через интерфейс. Активация документа понимания и публикация связки — отдельные действия пользователя. Обработка сигнала в очереди создаёт предложение: проверьте его до подтверждения прогресса или создания связки.

Маршруты отправки отчётов используют авторизованную сессию и выбранного пользователем получателя:

- `POST /api/summarize-email`: `consultation_id`, `email`, необязательный `summary_text`;
- `POST /api/diaries-summary-email`: `summary_id`, `email`, необязательный `summary_text`; без ID выбирается последнее саммари;
- `POST /api/retro-email`: `retro_id`, `email`, необязательный `retro_text`.

Запись уже должна быть завершена. Автоматическая отправка саммари консультации необязательна; ошибка email не отменяет готовое саммари. Ответ `200` отправки означает принятие вызова SMTP, а не открытие или даже получение письма адресатом.

## 6. Границы данных и ограничения эксплуатации

Telegram подтверждает личность. Netlify обрабатывает запросы. Neon хранит записи приложения. В режиме SendPulse провайдер получает сопоставленные поля профиля и контекста, а цепочки бота могут передавать пользовательский текст в приложение. При вызове ИИ-функции выбранные исходные материалы уходят в настроенный проект OpenAI. Публичные функции работы с ИИ задают `store:false`; само это значение не определяет все правила хранения и журналирования провайдера. Отправка email передаёт отчёт выбранному получателю и дополнительно заданному BCC.

Приложение не сканирует локальную историю компьютера, разговоры Codex, внешние диски или другие данные аккаунтов. Оно работает с переданными материалами и настроенными событиями интеграций. При этом состояние и отчёты могут содержать очень личную информацию. До её сбора объясните пользователям реальные сервисы, адресатов, сроки хранения и необязательную копию email. Репозиторий не предоставляет юридическую политику вашей организации или полный пользовательский сценарий удаления данных.

Входящие сервисные события — утверждения доверенного отправителя; они не доказывают понимание пользователем, завершённую консультацию или причину трудности. Выводы ИИ требуют проверки. Очереди, предложения и счётчики нельзя выдавать за установленные результаты.

**Ограничения доставки:** входящие события не обещают удаления повторов. Переменные SendPulse синхронизируются последовательно: ошибка может оставить часть внешних полей обновлёнными, хотя локальное сохранение завершится неуспешно. Общей транзакции между PostgreSQL и SendPulse нет. Перед повтором проверьте обе стороны. Смена адаптера в существующей установке не является автоматической миграцией данных: привязки контактов и внешние переменные нужно согласовать отдельно.

## 7. Проверка результата

Для первого запуска используйте только [вымышленные примеры](examples/README.ru.md) и свои тестовые аккаунты. Сохраняйте реальные результаты проверки в частном журнале; наличие инструкции не означает, что проверка пройдена.

| Проверка | Ожидаемое свидетельство |
| --- | --- |
| Сборка | `npm test` и `npm run build` проходят; ресурсы сайта публикуются из `dist` |
| Окружение и схема | Проверка настроек проходит; все миграции применены к нужной базе |
| Вход | Свежий Telegram-вход успешен; `/api/me` возвращает только вашего пользователя; просроченная или неверная авторизация отклоняется |
| Изоляция | Второй тестовый аккаунт не может использовать контакт первого или читать его записи |
| Состояние | Сохраните вымышленную задачу, корректный часовой пояс и время; перечитайте после перезагрузки; в режиме SendPulse проверьте и переменную контакта |
| Входящие цепочки | Пройдите всю [проверку SendPulse](sendpulse-setup.ru.md#5-проверка-установки-на-вымышленных-данных), включая ошибки и реальное тестовое сообщение по расписанию |
| Консультация | Загрузите [transcript.txt](examples/transcript.txt); увидьте `processing`, затем `completed` либо понятную ошибку; сверьте саммари с коротким исходником |
| Применение | Предпросмотрите выбранные поля, примените одно нужное изменение, перезагрузите и проверьте; не считайте невыбранные поля изменёнными |
| Дневники и обзор периода | Сформируйте отчёты за период, реально содержащий тестовые события; проверьте статус и показанное число исходных записей |
| Email, если включён | Отправьте вымышленный отчёт на свой адрес; проверьте получение и настройки копии |
| Восстановление | Восстановите тестовую копию в отдельную базу и откройте там те же вымышленные записи |

Даты в примерах событий вымышлены. Для проверки фильтров периода замените их датами своего теста; дата дневника всё равно определяется при получении. Проверяйте доставку напоминания отдельно от синхронизации переменных.

## 8. Резервное копирование, восстановление и обновление

Перед изменением схемы или провайдера приостановите соответствующие входящие цепочки и сделайте частную копию базы. Задайте `PRIVATE_BACKUP` как защищённый путь вне репозитория. Ниже команды для оператора; репозиторий сам их не выполняет:

```sh
pg_dump --format=custom --no-owner --file "$PRIVATE_BACKUP" "$NETLIFY_DATABASE_URL"
pg_restore --list "$PRIVATE_BACKUP"
```

Если используется `DATABASE_URL`, подставьте эту переменную подключения. Храните зашифрованные копии отдельно от ключей и задайте срок хранения. Копия содержит пользовательские данные и может содержать OAuth-токены. Также сохраните ревизию развёрнутого кода, историю миграций, частную опись конфигурации и собственный экспорт сценариев SendPulse либо заметки для их восстановления. Никогда не коммитьте секреты или резервные копии в публичный репозиторий.

Для учебного восстановления создайте пустую изолированную базу и задайте её адрес в `RESTORE_DATABASE_URL`. Восстанавливайте туда, а не поверх работающей production-базы:

```sh
pg_restore --no-owner --no-privileges --exit-on-error --dbname "$RESTORE_DATABASE_URL" "$PRIVATE_BACKUP"
```

Разверните соответствующую ревизию с тестовыми реквизитами и этой базой, затем повторите вход и проверку чтения. Старые сессии может понадобиться заменить; при подозрении на утечку смените кешированные и внешние реквизиты. Откат кода Netlify не отменяет миграции базы и изменения SendPulse.

Порядок обновления: зафиксировать текущую ревизию → сделать копию → просмотреть изменения и план миграций → проверить на отдельной базе → установить зависимости и выполнить тесты/сборку → применить ожидающие миграции → развернуть → повторить затронутые проверки. Не редактируйте уже учтённую миграцию ради совпадения контрольной суммы. Если новая схема несовместима с прежней версией, до обновления подготовьте восстановление базы или явное исправление следующей миграцией.

## 9. Разбор неполадок

| Симптом | Что проверить сначала |
| --- | --- |
| `bot domain invalid` | Домен BotFather, точный публичный HTTPS-хост, настроенное имя бота |
| `no_contact` / неизвестный контакт | Выполнен ли `/start`, правильный ли ID подставлен цепочкой, верен ли `SENDPULSE_BOT_ID`, пройден ли первый вход в приложение |
| Несовпадение контакта | Принадлежность Telegram-аккаунта, бота и контакта; не обходите проверку |
| Сохранение даёт `422` | `tz`, `t1`, `t2`, поддерживаемый часовой пояс, длины полей и диапазоны чисел |
| Сохранение успешно, но бот не меняется | `CABINET_TRANSPORT`, имя внешней переменной, её реальное использование в цепочке |
| Напоминание приходит не вовремя | Часовой пояс пользователя, `BOT_TIMEZONE`, импортированное время, сезонное смещение, настройка самого планировщика |
| Webhook даёт `401` | Нужный вид секрета и заголовок; `X-SP-Signature` — общий секрет дневника |
| ИИ отсутствует или завершается ошибкой | API-ключ, доступ проекта к модели, таймаут и токены, формат входа, статус задачи, очищенные журналы Functions |
| Письмо не отправляется | SMTP-реквизиты и порт, разрешённый отправитель, журналы доставки провайдера, адрес получателя |
| История пуста после deploy | Нужная база и контекст окружения, завершённая регистрация, все миграции |

В публичном сообщении об ошибке укажите ревизию, endpoint, HTTP-статус и минимальный вымышленный пример. Не прикладывайте токены, cookies, строки подключения, ID контактов, email-адреса, транскрипты и полные ответы с ошибками провайдеров.
