# Настройка SendPulse для Личного кабинета

Здесь описаны API публичного приложения и минимальный бот, который можно собрать в своём аккаунте. Это **не экспорт бота SendPulse**. В поставке нет графа исходных цепочек, расписаний, инструкций ИИ-агента, настройки распознавания голоса, тегов и данных подписчиков. После настройки нужно пройти проверку на собственном развёртывании; инструкция не означает, что эти действия уже проверены в живых сервисах.

Сначала выполните [инструкцию установки](operator-install.ru.md). Выберите `CABINET_TRANSPORT=sendpulse`: режим `local`, включённый по умолчанию, сохраняет состояние приложения, но не доставляет изменения переменных в SendPulse. Используйте своего Telegram-бота, свой аккаунт SendPulse и тестовых подписчиков.

## 1. Подключите бота и настройте регистрацию

1. Создайте бота через BotFather и подключите этого же бота к SendPulse. Сохраните токен только в серверном окружении Netlify как `TELEGRAM_BOT_TOKEN`, а имя без `@` — как `TELEGRAM_BOT_USERNAME`.
2. Получите API client ID/secret SendPulse и идентификатор подключённого бота. Задайте `SENDPULSE_CLIENT_ID`, `SENDPULSE_CLIENT_SECRET` и `SENDPULSE_BOT_ID`. Последний — идентификатор бота внутри SendPulse, а не имя Telegram-бота и не токен.
3. Через BotFather `/setdomain` привяжите домен HTTPS-приложения. Это требуется для [Telegram Login Widget](https://core.telegram.org/widgets/login/). Если используете кнопку Telegram Web App, настройте её на это же приложение и сохраните параметр контакта в ссылке.
4. В цепочке `/start` или приветствия SendPulse инициализируйте переменные из таблицы ниже и отправьте кнопку **Открыть Личный кабинет** со ссылкой:

   ```text
   https://YOUR_PUBLIC_ORIGIN/?sp_contact_id=CONTACT_ID_INSERTED_BY_SENDPULSE
   ```

   Вместо origin укажите свой адрес. Через выбор переменных в конструкторе вставьте **системный ID контакта подписчика**, а не Telegram ID, телефон или вручную заданный контакт. В документации SendPulse `contact_id` описан как [идентификатор подписчика](https://sendpulse.com/knowledge-base/chatbot/variable-types). До запуска проверьте подставленную ссылку тестового подписчика. `CONTACT_ID_INSERTED_BY_SENDPULSE` — поясняющая надпись, не выражение шаблонизатора SendPulse.
5. Тестовый подписчик отправляет `/start`, открывает кнопку и проходит вход через Telegram. Личность, подтверждённая подписью Telegram, должна совпасть с контактом, найденным для вашего SendPulse-бота. Сам по себе ID контакта в ссылке не даёт доступа.
6. При первом успешном входе приложение создаёт связь пользователя с контактом и импортирует сопоставленные переменные. Только после этого отправляйте события дневника и разбора: наличие подписчика в аудитории ещё не создаёт пользователя приложения.
7. В Личном кабинете выберите часовой пояс, утреннее и вечернее время, затем сохраните. Все три поля нужны для дальнейшего сохранения состояния. Проверьте соответствующие переменные контакта в SendPulse.

**Граница доступа:** после входа браузер использует cookie `lk_session`. Сервисный секрет и секрет дневника должны находиться только в серверных заголовках API Request. Не вставляйте их в ссылки кнопок, сообщения, переменные подписчика, клиентские скрипты или браузерные запросы.

## 2. Создайте переменные контакта

Имена в таблице точные: сохраняйте `№ дня`, суффиксы и ведущие нули. Сопоставленные поля читаются при первом входе и обновляются при каждом запросе приложения `GET /api/state-get`: значения провайдера объединяются с состоянием базы без создания версии. Сохранение в приложении отправляет изменённые поля обратно в SendPulse. Уже открытая страница не является живой подпиской: для просмотра изменений со стороны бота нужно обновить состояние.

Для текста и значений `HH:MM` используйте String. Числовые поля приложения принимают целые числа; адаптер API SendPulse отправляет значения строками, поэтому проверьте, принимает ли их выбранный числовой тип переменной SendPulse. Начните с вымышленных текстов без клиентских материалов.

| Поле приложения | Переменная SendPulse | Тип и ограничение | Значение и направление |
| --- | --- | --- | --- |
| `cycle_day` | `№ дня` | Целое 1–10 | День цикла; отправляется только при явном изменении, чтобы другое сохранение не сбрасывало счётчик бота |
| `t1` | `time_vopros_utro` | Строка `HH:MM` | Утреннее время; при отправке преобразуется из часового пояса пользователя в `BOT_TIMEZONE` |
| `t2` | `time_vopros_vecher` | Строка `HH:MM` | Вечернее время; такое же преобразование |
| `name` | `name` | Строка до 20 символов, без emoji | Отображаемое имя |
| `aff1` … `aff10` | `affirm_cont_1` … `affirm_cont_10` | Строки до 1 000 символов каждая | Десять личных формулировок для практики |
| `q1` … `q10` | `video_cont_1` … `video_cont_10` | Строки до 1 000 символов каждая | Десять слотов цитат или материалов; историческое имя `video_` не требует видео |
| `razbor_false_01` … `razbor_false_10` | Те же имена | Строки до 1 000 символов каждая | Сохранённые формулировки прежнего понимания |
| `razbor_new_01` … `razbor_new_10` | Те же имена | Строки до 1 000 символов каждая | Сохранённые формулировки нового понимания |
| `q_morning` | `vopros_utro` | Строка до 1 000 символов | Утренний вопрос |
| `q_evening` | `vopros_vecher` | Строка до 1 000 символов | Вечерний вопрос |
| `morning_algo` | `utro` | Строка до 1 000 символов | Текст утреннего порядка действий |
| `evening_algo` | `vecher` | Строка до 1 000 символов | Текст вечернего порядка действий |
| `gpt_standard` | `standard` | Строка до 1 000 символов | Личный ориентир или эталон |
| `gpt_format` | `format` | Строка до 1 000 символов | Желаемый формат ответа |
| `gpt_zapros` | `zapros` | Строка до 1 000 символов | Текущий запрос |
| `gpt_motiv` | `motiv` | Строка до 1 000 символов | Контекст мотивации |
| `gpt_situation` | `situation` | Строка до 1 000 символов | Текущий фокус; внутри приложения отражается также в `link_main` |
| `gpt_grabli` | `grabli` | Строка до 1 000 символов | Повторяющиеся трудности в формулировке пользователя |
| `gpt_talants` | `talants` | Строка до 1 000 символов | Контекст сильных сторон |
| `gpt_quotes` | `quotes` | Строка до 1 000 символов | Выбранные цитаты для контекста |
| `gpt_affirmation` | `affirmation` | Строка до 1 000 символов | Выбранная формулировка для практики |
| `gpt_mycontext` | `mycontext` | Строка до 1 000 символов | Дополнительный контекст пользователя |
| `affirm` | `affirm` | Строка до 1 000 символов | Формулировка текущего дня |
| `video` | `video` | Строка до 1 000 символов | Материал текущего дня |
| `msg_count` | `msg_count` | Целое 0–9 999 | Значение счётчика сообщений; правила увеличения и сброса ботом этот репозиторий не задаёт |
| `sprint_task` | `sprint_task` | Строка до 1 000 символов | Текст текущей задачи |

Только в базе хранятся `tz` (поддерживаемый часовой пояс IANA), `quote_pack` (`base` или `pro`), `link_main` и `link_add` (до 1 000 символов), `published_link_id` (UUID), `published_link_progress` (целое 0–999 999). Не создавайте их как цели синхронизации. `link_main` передаётся в SendPulse через зеркальную переменную `situation`. Изменение текста фокуса сбрасывает его счётчик прогресса в приложении. Стартовые общие тексты сохраняются в базе приложения; первый вход не отправляет их в SendPulse автоматически. Для изменения внешних переменных нужно явное сохранение или применение.

Каждая группа `razbor_*` вмещает до 10 000 символов, разделённых на десять слотов. При переполнении добавление сохраняет самый свежий конец текста. Это не архив всей истории без потерь: у сессий разбора есть отдельная история в базе.

**Работа со временем:** настройте расписание SendPulse в `BOT_TIMEZONE`. При исходящем преобразовании переход на летнее время рассчитывается по текущей дате. При первом импорте сохранённый часовой пояс пользователя ещё неизвестен, поэтому строки `HH:MM` нужно проверить. При последующем чтении состояния время бота преобразуется обратно в сохранённый часовой пояс пользователя. Проверьте их в приложении, сохраните с правильным часовым поясом и повторно проверьте напоминания при сезонном переводе часов. Сохранение переменных времени само по себе не создаёт планировщик или регулярную цепочку SendPulse.

## 3. Настройте входящие API-запросы

Элемент [API Request в SendPulse](https://sendpulse.com/knowledge-base/chatbot/send-receive-data) позволяет задать URL, заголовки, тело и обработку ответа. Доступность зависит от тарифа аккаунта. Выберите `POST`, JSON и endpoint **своего** приложения. Используются два разных вида авторизации.

| Endpoint | Заголовок | Обязательные поля | Что делает приложение |
| --- | --- | --- | --- |
| `/api/diary` | `X-SP-Signature: <SENDPULSE_DIARY_SECRET>` | `sp_contact_id`, `diary_text` | Сохраняет дневник; ставит сигнал связки в очередь; успех также записывает в таблицу успехов |
| `/api/razbor-session-ingest` | `X-LK-Service-Secret: <LK_SERVICE_SECRET>` | `sp_contact_id`, `summary_text` | Сохраняет запись завершённой сессии разбора |
| `/api/crm-activity-ingest` | Тот же сервисный заголовок | `sp_contact_id`, `source_ref_id` | Сохраняет CRM-событие; поле `text` дополнительно ставит сигнал связки в очередь |
| `/api/link-signals-ingest` | Тот же сервисный заголовок | `sp_contact_id`, `source_ref_id`, `text` | Ставит сигнал в очередь для последующего анализа и проверки |

Все четыре маршрута также принимают `Authorization: Bearer <соответствующий секрет>`. Заголовок `X-SP-Signature` передаёт **общий секрет**, а не HMAC-подпись тела. Добавьте `Content-Type: application/json`. Последние два маршрута допускают и авторизованную браузерную сессию; бот должен использовать сервисный заголовок и явный ID контакта.

### Запись дневника

Скопируйте [diary.json](examples/diary.json), замените вымышленный контакт своим тестовым и подставьте полученный текст в `diary_text`. `source` по умолчанию равен `sendpulse_voice`; поддерживаются:

- `sendpulse_voice` — обычный дневник или расшифрованное сообщение;
- `sendpulse_success` — успех; дополнительно попадает в таблицу успехов;
- `sendpulse_new` — замеченное новое;
- `sendpulse_idea` — идея.

Форма ответа: `{"ok":true,"id":"<UUID записи>","user_id":"<UUID пользователя>","local_date":"<YYYY-MM-DD>","created_at":"<время>"}`. Дата вычисляется при получении в часовом поясе пользователя. Время события у бота её не переопределяет. Если задан текст фокуса, success/new/idea также увеличивают его текущий счётчик прогресса; обычный дневник — нет. Этот счётчик отражает события продукта, а не независимое доказательство психологического результата.

### Завершённая сессия разбора

Скопируйте [razbor-session.json](examples/razbor-session.json). `summary_text` очищается от крайних пробелов и ограничивается 12 000 символами. Необязательные поля: `status` (по умолчанию `completed`), `source` (по умолчанию `sendpulse_ai_agent`), `occurred_at` (ISO timestamp; без него берётся время получения). Отправляйте `completed` только после формирования итогового текста вашим сценарием. Endpoint сохраняет переданный текст: он не запускает ИИ-диалог, не заполняет слоты `razbor_*` и не подтверждает результат консультации. Ответ: `{"ok":true,"item":{...}}`.

### CRM-событие

Скопируйте [crm-activity.json](examples/crm-activity.json). `event_type` принимает `evening_plus`, `task_done` или `other` (по умолчанию). `source_ref_id` — непустая ссылка-идентификатор, которую создаёт ваша цепочка. `value_text` — необязательный текст, `value_number` — необязательное конечное число, `payload` — необязательный JSON-объект, `occurred_at` — необязательная корректная дата ISO. Непустое поле `text` создаёт сигнал `crm_evening` в очереди. Ответ: `{"ok":true,"item":{...},"signal":...}`.

### Отдельный сигнал

Скопируйте [link-signal.json](examples/link-signal.json). `source_type`: `diary_entry`, `crm_evening`, `crm_reaction` или `manual` (по умолчанию). `source_created_at` — необязательная корректная дата ISO. Ответ: `{"ok":true,"item":{...}}`. Не отправляйте сюда повторно дневник, уже переданный в `/api/diary`: тот маршрут сам создаёт сигнал.

### Ответы, повторы и видимость ошибок

`200` и `ok:true` означают сохранение. `400` — ошибка тела, `401` — неверный секрет, `403 contact_binding_failed` при входе — несовпадение личности и контакта, `409 contact_binding_changed` — попытка изменить существующую привязку, `404` при приёме события часто означает, что подписчик ещё не вошёл в приложение, `429` — ограничение частоты сервисных запросов, `500` — повод проверить настройки и журналы развёртывания. При неуспешном запросе показывайте сообщение о повторной попытке, а не подтверждение сохранения.

Эти маршруты **не обещают идемпотентной доставки**: `source_ref_id` — ссылка на источник, а не универсальный ключ удаления повторов. Таймаут возможен уже после записи. Не делайте слепой автоматический повтор: сначала найдите тестовое событие в приложении, затем решите, нужно ли отправлять его ещё раз. Отдельной панели сверки доставки цепочек бота в этой версии нет.

## 4. Вручную соберите минимальные цепочки

Создавайте и проверяйте цепочки отдельно. Ниже — **новый минимальный рецепт настройки**, а не восстановленная копия частного бота.

| Цепочка | Последовательность в конструкторе | Граница |
| --- | --- | --- |
| Регистрация | `/start` → объяснение хранения и внешних сервисов → заполнение отсутствующих переменных → кнопка приложения с ID контакта → просьба завершить вход | Повторный `/start` не должен перезаписывать уже настроенные переменные |
| Текстовый дневник | Меню/кнопка → ввод текста → API Request `/api/diary` → ветка успеха или ошибки | Для голоса отдельно настройте распознавание речи; URL аудиофайла не является транскриптом |
| Успех / новое / идея | Меню/кнопка → ввод текста → тот же API дневника с нужным `source` → ветка результата | Не отправляйте тот же текст вторым дневником или сигналом |
| Утро / вечер | Ваш запуск по расписанию → чтение выбранного вопроса и порядка действий → сообщение → при необходимости ответ в API дневника | Планировщик, тихие часы, выходные, увеличение дня цикла и перенастройка после правок реализуются в SendPulse |
| Завершение ИИ-разбора | Ваш утверждённый ИИ-сценарий → явный итоговый текст → `/api/razbor-session-ingest` → подтверждение | Промпт, модель, условие завершения, сбор контекста и передача человеку задаются оператором; OpenAI-настройки приложения не настраивают ИИ-блок SendPulse |
| Внешнее событие задачи, необязательно | Доверенный сигнал завершения → `/api/crm-activity-ingest` | `task_done` отражает утверждение отправителя, а не автоматическую проверку выполнения |

В каждом API Request вставляйте системный ID контакта и полученный текст через выбор переменных. Проверьте кавычки, переводы строк, emoji и длинный ответ, чтобы убедиться в правильном JSON-экранировании. Используйте JSON-редактор или сопоставление полей конструктора вместо склеивания пользовательского текста со строкой JSON. Для отладки можно сохранять возвращённый ID записи или сессии в отдельно созданную переменную оператора; она не входит в карту состояния приложения.

Переменные промпта — это **данные**: этот репозиторий не делает их автоматически исполняемыми инструкциями бота. Определите и опишите, какие поля читает ваш ИИ-сценарий SendPulse. Наличие десяти слотов не устанавливает десятидневную программу. Этот комплект не устанавливает правило «Десятки» в 22:00, исходные учебные материалы или исходный частный консультационный сценарий.

## 5. Проверка установки на вымышленных данных

1. Используйте новое развёртывание, новую базу и два тестовых Telegram-аккаунта под вашим управлением. Подключите первый через `/start`; `/api/me` должен авторизоваться только после входа через Telegram.
2. Откройте ссылку первого контакта под вторым аккаунтом. Проверка связи личности с контактом должна отказать. Затем зарегистрируйте второй аккаунт по его собственной ссылке и убедитесь, что записи первого ему не видны.
3. Задайте в Личном кабинете часовой пояс и время. Сохраните `sprint_task`: «Вымышленный тест: одно учебное упражнение». Проверьте переменную SendPulse и состояние приложения после перезагрузки.
4. Отправьте пример дневника, заменив контакт на свой тестовый. Должны появиться ровно один дневник и, для `sendpulse_success`, одна запись успеха. Сверьте `local_date` с часовым поясом пользователя.
5. Отправьте пример сессии разбора и найдите его в истории. Отправьте примеры CRM и отдельного сигнала с разными ссылками на источник. Сигналы в очереди не становятся проверенными выводами до явной обработки и проверки в приложении.
6. Пройдите цепочку текстового дневника из Telegram целиком. В тестовой цепочке проверьте неверный секрет и незарегистрированный контакт: дневник не должен сохраниться, а сообщение об успехе — появиться.
7. Поставьте тестовое напоминание на несколько минут вперёд. Проверьте получение на устройстве, затем измените время в приложении и убедитесь, что цепочка использует обновлённую переменную. Успешная запись переменной ещё не доказывает доставку по расписанию.
8. Запишите версию развёртывания, дату, проверенные функции, настройки провайдеров и ошибки в **частный** журнал приёмки. До прохождения проверок называйте установку настроенной, а не проверенной.

Все [тестовые материалы](examples/README.ru.md) вымышлены. Заглушки контактов намеренно не указывают на действующий аккаунт.
