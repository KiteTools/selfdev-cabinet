# Как заменить транспорт

[English](transports.md) · [Русский](transports.ru.md)

Обработчики приложения обращаются к `netlify/functions/lib/transport.js`. Фабрика выбирает адаптер по `CABINET_TRANSPORT`. Реализация SendPulse находится в `lib/transports/sendpulse.js`; реализация без доставки — в `local.js`. Старый `lib/sendpulse.js` сохранён только для совместимости и всегда вызывает SendPulse; обработчики приложения его не импортируют. Новый код должен использовать `transport.js`.

| Метод | Результат и ответственность |
| --- | --- |
| `kind` | Стабильное имя транспорта: `local` или `sendpulse` |
| `resolveContactForTelegram({ telegramUserId, requestedContactId })` | Возвращает проверенный контакт с `id` или `null`. Никогда не доверяет одному ID, пришедшему из браузера. SendPulse сверяет Telegram ID, ID контакта и ID настроенного бота по ответу провайдера. |
| `getContact(id)` | Возвращает контакт либо `null`; ошибки провайдера не должны возвращать его личный payload. |
| `getContactVariables(id)` | Возвращает карту полей для существующего слоя преобразования состояния. Новый провайдер должен адаптировать свои поля к тому же договору. |
| `setVariable(id, name, value)` | Обновляет одно поле либо явно сообщает об ошибке/отсутствии доставки. |
| `syncVariables(id, values)` | Обновляет карту полей и возвращает `{ transport, delivered, reason? }`. В SendPulse `delivered:true` означает успешные ответы API на обновление полей, не прочитанное сообщение Telegram. |

В `local`-режиме внешний контакт имеет внутренний ключ `local:<telegram_id>`, чтение внешних переменных возвращает пустую карту, а отправка возвращает `delivered:false`, `reason:delivery_disabled`. Приложение хранит состояние в своей базе. Telegram-вход, сервер и база остаются нужны.

Для нового адаптера реализуйте методы, добавьте ветку фабрики, список допустимых значений в проверке окружения и соответствующие тесты. Доступы остаются на сервере. Тестируйте два разных аккаунта, недоступность провайдера, частичный сбой отправки, повторный вход и сохранение без доставки. Учётная запись пользователя принадлежит приложению; текущая схема всё ещё использует совместимые технические имена `sendpulse_contact_id`, а преобразование переменных сохраняет прежнюю карту полей. Это не автоматический перенос учётных записей между провайдерами.

При смене транспорта в уже заполненной базе текущая привязка не заменяется автоматически. Вход с другой привязкой возвращает `contact_binding_changed`; оператор должен отдельно спланировать перенос, сохранить копию и проверить принадлежность записей. Прямой Telegram-бот в поставку не включён.

Адаптер SendPulse ограничивает сетевое ожидание, обновляет токен после 401 и ограниченно повторяет 429. Обновления нескольких переменных не являются одной транзакцией: часть может успеть примениться перед ошибкой. Надёжная исходящая очередь, общий механизм повторов и дедупликация входящих событий пока не реализованы. Не включайте слепой автоповтор входящих webhook-записей. [Настройка сценариев и ограничения](sendpulse-setup.ru.md).
